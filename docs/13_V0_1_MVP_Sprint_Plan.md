# AI 小手机 - V0.1 (Genesis) 最小可行性产品开发冲刺计划

## 1. 目标定义
在单一开发周期内，跑通端侧大闭环：从“角色导入” -> “上下文检索与组装” -> “云端 LLM 推理” -> “双端（聊天/朋友圈）UI 渲染”。

## 2. 阶段拆解与实施顺序 (Phased Execution)

我们必须按照“数据流入 -> 逻辑处理 -> 数据流出”的顺序来开发，避免前后端互相等待。

### Phase 1: 基础设施与数据基座 (Data Ingestion)
* **任务 1**: 搭建 Android Studio 工程，配置 Kotlin + C++ (CMake) 的 JNI 互调环境。
* **任务 2**: 实现 SQLite 的建表（预设表、世界书表、聊天记录表、朋友圈状态表）。
* **任务 3**: **[MVP目标达成]** 开发 C++ 的 `CardParser`，跑通从相册读取 SillyTavern V2 PNG 图片，提取 JSON 并写入 SQLite 预设表。

### Phase 2: 核心大脑与网络通信 (Logic & Network)
* **任务 4**: 实现“系统设置 App”，在 Kotlin 层完成 API Key 的输入与加密存储。
* **任务 5**: **[MVP目标达成]** 开发 C++ 的 `PromptEngine` 和 `WorldBook_Scanner`。实现简单的字符串匹配算法，将用户输入与世界书词条结合，拼装成最终的 Prompt。
* **任务 6**: Kotlin 端实现网络请求模块（如使用 OkHttp），接收 C++ 传来的 Prompt，请求大模型，并将流式/完整返回结果写回 SQLite。

### Phase 3: 视觉表现与双端输出 (UI & Action)
* **任务 7**: 开发「聊天 App」UI，实现基础的文字气泡列表，绑定 SQLite 数据库进行实时刷新。
* **任务 8**: **[MVP目标达成]** 开发「朋友圈 App」UI。在 C++ 层实现一个极其简易的“发朋友圈指令（Action）”解析。让 AI 在特定对话后（或者通过一个手动的调试按钮）触发生成一条朋友圈数据，并显示在 UI 瀑布流中。

## 3. V0.1 验收标准 (Definition of Done)
1. 导入一张外部酒馆角色卡，系统能正确识别并创建联系人。
2. 发送消息，AI 能根据卡片设定准确回复。
3. 输入触发词，AI 能感知世界书设定的内容。
4. AI 能够成功发布一条带有文字的虚拟朋友圈动态。
