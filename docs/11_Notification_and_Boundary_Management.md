# AI 小手机 - 通知与次元边界管理 (Notification & Boundary)

## 1. 核心原则
**“平行世界原则”**：小手机内发生的所有事件、消息、状态变更，绝对不溢出到宿主（真实）Android 系统的通知栏。小手机是一个封闭的沙盒宇宙。

## 2. 后台与休眠机制 (App Lifecycle)

### 2.1 退至后台 (Background)
* 当用户将“小手机”退到后台时，前端 Kotlin 的 UI 渲染暂停。
* C++ 的**时间引擎 (Time Engine)** 和 **主动事件调度器 (Proactive Scheduler)** 继续运作。
* 我们依赖 Android 的 `WorkManager` 设置定期的后台唤醒（例如每 15 分钟一次，或者根据虚拟日历事件动态设定唤醒时间）。

### 2.2 离线演算 (Offline Simulation)
* 当后台任务触发时，C++ 引擎检查系统状态（例如：距离上次聊天过去了多久？触发了什么事件？）。
* 如果决定发消息，网络层向大模型发起请求，收到回复后静默写入 SQLite 的 `messages` 表，并更新系统的“未读消息数”。
* **无物理通知**：在此过程中，不调用任何 Android `NotificationManager` 的弹窗或震动。

## 3. 回归与追赶机制 (Catch-up Sequence)

### 3.1 唤醒重绘
* 当用户重新切回“小手机”App 时，UI 立即读取 SQLite 的最新状态。
* 用户看到的第一个画面将是**高仿的虚拟锁屏**，屏幕上堆叠着离线期间 AI 积累的虚拟通知（如：`[微信] 2条未读`、`[备忘录] 提醒...`）。

### 3.2 离线时间快进 (Time Forwarding)
* 为了防止应用被系统彻底杀死导致后台任务中断，每次 App 前台冷启动时，C++ 引擎需要计算 `当前真实时间 - 上次退出时间`。
* 根据计算出的时间差，C++ 执行一次**快进演算 (Fast-forward Simulation)**，瞬间结算离线期间错过的所有状态变化（好感度衰减、外卖送达等），确保数据的连贯性。
