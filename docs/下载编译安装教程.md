## 方法一：直接安装 APK（适合普通用户）

如果仓库的 **Releases** 页面已经提供 APK：

1. 打开官方仓库，点击右侧的 **Releases**。
2. 进入最新版本，在 **Assets** 中下载以 `.apk` 结尾的文件。
3. 在安卓手机上打开下载的 APK。
4. 如果系统提示“禁止安装未知应用”，进入系统设置，临时允许当前浏览器或文件管理器安装未知应用。
5. 返回安装界面，点击“安装”。

如果 Releases 页面暂时没有 APK，请使用下面的源码编译方法。不要从陌生网盘或付费店铺下载所谓“官方版”。

## 方法二：下载源码并用 Android Studio 安装

### 1. 准备工具

在电脑上安装：

- [Git](https://git-scm.com/downloads)
- [Android Studio](https://developer.android.com/studio)
- 一根能够传输数据的 USB 线

Android Studio 自带运行项目所需的 JDK。第一次构建时需要联网下载 Gradle 和 Android 依赖。

### 2. 下载源码

可以选择任意一种方式。

使用 Git：

```powershell
git clone https://github.com/w1990709164-bot/Mji.git
cd Mji
```

或者在 GitHub 仓库页面点击 **Code → Download ZIP**，下载后解压。

### 3. 用 Android Studio 打开

1. 启动 Android Studio。
2. 点击 **Open**。
3. 选择解压后的 `Mji` 文件夹，而不是只选择里面的 `app` 文件夹。
4. 等待右下角的 Gradle 同步和依赖下载完成。
5. 如果提示安装缺少的 Android SDK，点击提示中的安装按钮并接受许可。

### 4. 连接安卓手机

1. 打开手机的“设置 → 关于手机”。
2. 连续点击“版本号”约 7 次，开启开发者选项。
3. 在“开发者选项”中打开 **USB 调试**。
4. 用数据线连接电脑，并将 USB 用途设为“文件传输”。
5. 手机上出现“是否允许 USB 调试”时，勾选“始终允许”并点击“允许”。
6. 回到 Android Studio，等待顶部设备列表出现手机名称。

### 5. 编译并安装

在 Android Studio 顶部确认运行配置为 `app`，设备选择自己的手机，然后点击绿色三角形 **Run**。

也可以在项目根目录运行：

```powershell
.\gradlew.bat :app:assembleDebug
```

Windows 生成的调试 APK 位于：

```text
app\build\outputs\apk\debug\app-debug.apk
```

把这个 APK 发送到手机后也可以手动安装。

macOS 或 Linux 使用：

```bash
./gradlew :app:assembleDebug
```

## 常见问题

### Android Studio 显示 `No target device found`

这表示电脑没有识别到可运行的安卓设备，与源码编译失败无关。请依次检查：

1. 手机是否已经开启 USB 调试。
2. 手机是否确认了 USB 调试授权弹窗。
3. USB 线是否支持数据传输；部分线只能充电。
4. USB 模式是否选择“文件传输”。
5. Windows 是否安装了手机品牌的 USB 驱动。
6. 在 Android Studio 的 **Device Manager** 中重新连接设备，或创建安卓模拟器。

可以在终端检查设备：

```powershell
adb devices
```

如果状态为 `unauthorized`，请解锁手机并确认 USB 调试授权；如果列表为空，请更换 USB 接口或数据线并检查驱动。

### Gradle 同步或下载失败

- 确认电脑可以访问依赖下载站点。
- 点击 **File → Sync Project with Gradle Files** 重试。
- 不要随意删除或修改 `gradle`、`gradlew` 和 `gradlew.bat`。

### APK 提示无法安装

- 如果手机中已有签名不同的同包名版本，请先备份数据，再卸载旧版本。
- 确认手机允许当前文件管理器安装未知应用。
- 重新下载 APK，避免文件损坏。

## 首次运行

M叽已经移除原先的账号登录流程，安装后可以直接进入应用。API、TTS 和 MCP 等在线功能仍需根据设置页面填写或确认相应服务配置；请勿把自己的 API Key 发布到 Issues、截图或公开仓库中。
